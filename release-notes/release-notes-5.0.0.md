# TuxunDown v5.0.0

5.0.0 是 4.1 以来的整合版。这一版没有堆新功能，而是把 4.x 做过的所有功能做了一次全面交叉检查和回归核对：逐项确认该在的功能都真的接上了线、旧修复没有回退，还专门检查了功能和功能交叉时会不会互相影响。核对的结论是功能都在、无回退；交叉检查另外抓出两个藏在功能交叉处的问题，已经修好（见下面「修复」）。4.x 累积的速度成果都保留着，这一版把它们汇总在下面，方便一次看清。下面只讲具体改了什么，不承诺任何速度倍数。

## 速度（4.x 汇总）

- **连接开得更多、也管得住**：单个任务最多 64 条连接同时下载；所有任务合计有全局连接上限，可在设置里调（8–128 条、默认 32），多任务同时下时按优先级分摊，被压住的任务卡片上会写明。
- **爆发开局**：新任务不再从一两条连接慢慢爬，先 16 条一起开局，再按实际速度自动加减——速度不再涨就收下来，不瞎开。
- **连接预热**：有任务在下时，排第一位的下一个任务会提前把连接建好，轮到它时开局更快。预热只在 WiFi 或双通道时做，流量保护开着、用了代理时不做。
- **相邻分片合并**：挨在一起的小分片会合并成一次请求下完，请求次数更少，下载更利落；任务的登录 Cookie 只发给原站，合并和跳转都不会把登录状态带到别的站。
- **连接数对比实测，测完能直接用**：诊断页可以拿同一个链接轮流实测 4 / 16 / 32 / 64 条连接哪一档最快；测出最快档后可以一键写回对应站点，以后从这个站下载直接按那一档起步；设置里也能清除按主机学到的数据，改回自动。
- **HLS 流媒体并发自适应**：m3u8 流媒体下载的分段并发会按实际速度自己增减，站点快就多开、慢就收着下，更快也更稳。
- **FTP 多连接分片**：FTP 服务器支持断点续传时，最多 8 条连接分片同时下（FTP 服务器对同时连接数普遍管得严，所以上限比普通下载低）；不支持时自动单连接，卡片上写明原因。
- **息屏不降速**：真正下载时会保持处理器运行，息屏后大文件下得更稳；任务结束立刻放开，排队等待不占用。这个开关默认开着，设置里可以关，代价写在开关旁边：开着更费电。

## 修复

- **等充电时不再白白预热连接**：开了「充电时才下载」、又没插电的时候，排队的任务本来一个都开始不了，但排第一位的任务还是会被提前预热连接——连接建好了也用不上，只能白白耗电等它过期。现在这种情况下不再预热，插上电、任务真能开始了才预热。
- **需要登录的镜像不再被误报「对不上」**：用多个镜像加速时，下载前会逐个校验镜像是不是同一个文件。以前镜像在别的站点、又需要登录时，校验拿不到它的数据，就会被当成「文件对不上」拒绝，卡片说法也不准。现在分清三种情况：确认是同一个才用；确认对不上才拒绝；没能确认的（比如需要登录）不会算作对不上，卡片会写明「没能确认，可能需要登录，已先不用」——没确认过的镜像仍然不会参与下载，不会把没验过的数据拼进文件。
- **历轮审计的修复都还在**：这轮把 1.2 到 4.9 的功能点逐项对着代码核了一遍（共 88 项），包括历轮审计修过的问题，确认没有一项掉线、没有一处旧修复回退；这一轮除了上面两处，没有再需要修的地方。

## 新增（4.x 汇总）

- **服务器画像**：展开任务详情能看到这个任务实际下载里记下的数据——服务器支不支持断点续传、报的文件大小、实际峰值连接数、每个下载源各下了多少。没探到的就不显示，不猜。
- **队列按站点轮转**：同一优先级里，不同网站的任务轮流开始，一长串同站任务不会把别的站一直饿着；优先级仍然说了算，手动插队仍然最优先。
- **失败原因按类型记录**：失败在出错那一刻就按类型记下（空间不够、文件被换过、被限流、链接失效、需要登录等），失败卡片的处理建议和自动重试都按类型判断，重启后照样准，不再靠猜错误文字。
- **测速历史**：内置测速的结果会留最近 10 次，方便前后对比网络变化。
- **通知栏聚合剩余时间**：多个任务一起下时，通知栏会按总进度写明「全部还剩 大约 X 分钟」，和主页汇总卡同一套估算口径；有任务大小未知或暂时没速度时就不显示，不写假数字。
- **公共 WiFi 门户停泊**：连上需要先登录的公共 WiFi 时，任务会先停下等你完成登录，然后自动继续，登录页不会被当成文件存下来；中途切网、开飞行模式造成的断网同样是先停泊、恢复后自动继续，不直接判失败。

## 说明

- 升级方式不变：正式签名与之前一致，直接覆盖安装即可，不用卸载，任务记录都保留。
- 没有新增任何权限；没有新增任何第三方依赖。本版的两个修复和全量回归核对都有单元测试或代码核对钉住，帮助中心也同步补齐了 4.x 的新话题（连接数怎么选、息屏不降速、FTP 多连接、站点轮转、门户停泊、失败建议、服务器画像）。
- 安装包体积：以正式发布包实测为准（仍在 1.5 MB 红线内）。
