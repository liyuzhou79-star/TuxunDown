# TuxunDown v4.0.0

4.0.0 是个收尾版，做三件事：修好主页进度不实时刷新的老毛病、让分片下载的连接能复用再快一点、把内置测速的算法换成更公平的口径并把结论说清楚。三件都来自实际使用中碰到的问题：进度要切页回来才动、测速里多线程那段数字明显偏低、块数多的大文件每块都要重新握手白白耗时。

## 修复

- **主页进度改为实时刷新**：以前停在主页看下载，进度条、速度和剩余时间都不动，要切到别的页面再切回来才更新一次。根因说白了是：下载引擎每秒都在算新数据，但主页的界面没有跟着这份每秒数据走，只有重新打开页面时才会读到最新值。现在改好：停在主页不动，进度条、速度、剩余时间每秒自己刷新；展开任务详情后，分片进度图和每条连接的速度也同步更新；统计页同理，停在那一页就能看到数字动。看得见的列表项才刷新，滑出屏幕的不浪费资源，滑动流畅度不受影响。

## 优化

- **分片连接改为复用，下载再提速**：以前每下完一块，连接就直接断开，下一块要重新走一遍连接建立和加密握手，块越多、白付的握手时间越多。现在改成：内容完整读完的连接不断开，放回连接池给下一块接着用；只有没读完就中断的连接才断开重连（半截数据不能复用，这是规矩）。大文件、分片多的下载更明显。
- **淘汰卡死连接不再堵住其他连接**：顺手修了一处内部卡顿——之前清理卡死连接的动作是在大家共用的锁里面做的，断开一条卡住的连接时，其他连接都得排队等着。现在改成先在锁里把要清理的连接挑出来、释放锁之后再逐条断开，清理归清理，不耽误正常下载。

## 测速

- **改用稳态口径，两段同尺**：以前的算法把「从点下开始到全部结束」的总时间直接拿来算平均速度，连接建立、加密握手和开头爬坡那段慢时间全算了进去。多线程那段要同时建四条连接，付的慢时间是单线程的四倍，数字就被系统性地拖低——测出来「多线程没快多少」，有一部分是算法冤枉的。现在两段都只算稳定下来的那段速度：开头约 1.5 秒的爬坡不计入，用采样点算稳态区间的速度；测太短、采样不够时退回整段平均，不编数字。
- **结论改成三档，说清原因**：以前结论只有两档，多线程哪怕只有单线程的一半，也只会显示「没比单线程快多少」，是错话。现在分三档：多线程明显更快（达到单线程的 115% 以上）、两边差不多、反而更慢（不到单线程的 85%），每一档都写明可能的原因和建议——比如反而更慢时，建议把连接数调低再试。
- **标注实测时长**：单线程和多线程两行的结果旁都会标出这段速度实际测了约多少秒，数字是怎么来的，一眼能看清。

## 说明

- 升级方式不变：正式签名与之前一致，直接覆盖安装即可，不用卸载，任务记录都保留。
- 没有新增任何权限；没有新增任何第三方依赖。测速的稳态计算和三档结论都是纯算法，带单元测试（含 115% / 85% 的边界用例）。
- 安装包体积：以正式发布包实测为准（仍在 1.5 MB 红线内）。
