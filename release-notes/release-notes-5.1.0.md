# TuxunDown v5.1.0

5.1.0 这一版主要照顾内存比较小的手机。下载时占用的内存会按设备情况自动分档：内存小的机器自动收紧，多个大文件一起下也不容易把内存撑爆；内存大的机器则略放宽一点。同时，流媒体下载在内存里的占用改成所有任务一起算的全局封顶，启动和主页也做了一轮流畅方面的修缮，诊断页多了两行能直接看的信息。下面只讲具体改了什么，不承诺速度倍数——这一版的重点是低端机更稳，高内存机器的缓冲略放宽。

## 内存分档

- **下载缓冲按设备内存自动分档**：App 会看这台手机的内存档位，自动决定每个下载任务能用多少缓冲。内存小的档位收紧到更省的用法，内存大的档位略放宽。档位是自动定的，没有多加开关，也不用你手动调；缓冲大小只在任务开始时定下来，正在下的任务不会中途被改。
- **多个大文件一起下更不容易爆内存**：以前每个任务各自按自己的上限占内存，任务一多，总量就容易顶上去。现在普通下载的单任务缓冲随档位收紧，低端机同时下几个大文件时，内存账更可控，不容易因为内存不足被系统杀掉或闪退。

## 流媒体内存封顶

- **HLS 大分片改成全局封顶**：m3u8 流媒体下载时，分片在内存里的占用以前是每个任务各算一份，单个很大的分片还可能绕过上限。现在改成所有流媒体任务一起算的全局预算，并随内存档位调整；单个分片也有与档位对应的大小上限，太大的分片会停下来并在任务上说明原因，不会硬塞进内存。低端机下流媒体，不再有爆内存的最坏情况。
- **普通播放列表不受影响**：常见的流媒体分片都不大，下载和合并的节奏和以前一样，这次改的是极端情况下的上限，不是日常速度。

## 启动与主页流畅修缮

- **启动路径复查干净**：这一轮把打开 App 到第一屏之间的每一步重新查了一遍，确认没有多余的初始化挤在第一屏之前，该在第一屏之后做的事都还在后面。
- **主页卡片更跟手**：任务卡片上的「服务器画像」以前每次刷新都会把整份站点记录重新解析、重新汇总一遍，卡片展开时每秒都在重复算。现在改成数据没变就不重算、变了才算，低端机滑动列表、看卡片时会更跟手。

## 诊断页新增两行

- **能看内存档位**：诊断页会直接写明这台手机当前是哪一档、每个下载任务的缓冲上限大约是多少；复制诊断报告时这一行也会带上，报问题时对方一看就知道你的机器是什么情况。
- **能看上次启动耗时**：诊断页还会显示上一次冷启动到第一屏大约用了多少毫秒。这个数字只存在本机、不上传；第一次安装还没测到时就不显示，不会编一个假数字。打开 App 觉得慢时，可以先看这一行再判断。

## 说明

- 升级方式不变：正式签名与之前一致，直接覆盖安装即可，不用卸载，任务记录都保留。
- 没有新增任何权限；没有新增任何第三方依赖。
- 安装包体积：以正式发布包实测为准（仍在 1.5 MB 红线内）。
