# TuxunDown v2.7.0

2.7.0 做三件事：快捷入口——快捷设置磁贴、主页汇总卡的「全部暂停 / 全部继续」、长按图标快捷方式，都连到同一套队列控制上；失败诊断建议——失败卡片按原因给一句能照着做的建议和直达按钮；第 13 轮审计（长跑稳定性）——修了一个分片下载重试路径上的连接泄漏，并把持续满线程下载数小时的内存、CPU 与发热降频行为逐项核了一遍。统计页另加了最近 7 天下载量柱状图。

## 新功能

- **快捷设置磁贴**：下拉通知栏、点编辑，把「TuxunDown 下载」磁贴加进面板。磁贴上直接写着正在下几个；点一下全部暂停，再点一下全部继续。状态每次打开面板都会重新读，不会显示过期的数字。磁贴和主页用的是同一套判断逻辑（有任务在下或排队就给「全部暂停」，全停着才给「全部继续」），不会出现两个地方说法不一致。
- **主页汇总卡「全部暂停 / 全部继续」按钮**：和磁贴共用同一逻辑、同一条执行路径。汇总卡以前要在至少 2 个任务进行中时才出现；这一版当全部任务都暂停着（2 个以上）时它也会出现——那正是「全部继续」最有用的时候，卡上会写明「任务都暂停了」，不会拿一个 0% 的假汇总糊弄。
- **长按图标快捷方式**：「新建下载」直接打开新建弹窗；「打开嗅探」直接打开嗅探浏览器（空白页，自己导航到要抓的页面，和从新建弹窗里打开它一样）。
- **失败诊断建议**：失败任务展开详情，除了失败原因，还按类别给一句建议，带直达按钮的都是一键能到的地方：被拒（403/401）→ 建议用内置浏览器打开原网页、登录后在页面里点下载（Cookie 自动带上），按钮直达浏览器；空间不够 → 按钮直达「已下载文件」去清大文件，清完点继续就续传；文件被中途换掉/对不上 → 有镜像源时按钮直达镜像管理，建议删掉可疑的源只留主地址；限流（429）→ 等几分钟再继续，并说明线程数是自动调的、不用改设置；服务器不支持分片 → 说明会单线程从头下、期间尽量别暂停；网络类 → 建议换网络排除当前网络的问题。文件已删除（404）这类重试也没用的，只给说明、不摆假按钮；认不出的失败不瞎猜，不给建议。
- **统计页「最近 7 天下载量」柱状图**：和速度曲线同款的绿色手绘图，最后一天是今天。**如实说明**：以前的版本只存了「今日」一天的量，没有 7 天的历史数据可以复用——按天记录从这一版才开始。今天的量是完整的（用的是今日总计），前面几天会随使用一天天记满；在那之前图上是真实的 0，不会拿别的数据补。

## 优化（第 13 轮审计：长跑与发热）

- **修了一个连接泄漏（坐实）**：分片下载里，某条连接读到一半出错（连接被重置、读超时等）时，异常路径跳过了关流和断开连接的代码。调用方对每个分片会重试最多 3 次，服务器不稳时一个长下载能失败几百次——每次都漏一条连接，socket 只能等系统回收，几个小时下来可能攒到影响后续连接。现在释放动作进了 finally，出错、暂停、被淘汰、正常下完，每条路都关。顺带修了一个同类小问题：下载线程退出时不再把已死的线程对象留在列表里（线程池伸缩几小时也会攒）。
- **内存随任务数/时长的增长（核过，有界）**：每个任务的速度采样固定只留最近 90 个点（写入和读取两头都截断）；分片位图按文件大小/分片大小定长，分片大小本身是自适应的，不会随下载时长增长；流媒体分段表有条数上限钳制。任务记录的落盘保存是合并写的（最多 1.5 秒一次、单线程排队），任务再多也不会变成每秒多次全量写盘。
- **CPU 热点（核过）**：进度通知的构建有约 900 毫秒节流，多个任务并发时走的是同一条聚合通知路径；采样器是固定 1 秒节拍的 deadline 调度，没有忙等；下载主线程靠 join 等待工作线程结束（v2.2 起），不轮询。
- **发热降频会不会误杀慢连接（核过，逻辑本来就防着）**：淘汰一条「12 秒没动静」的连接有个前提——同一时刻整个任务还在前进（有别的连接在出字节）。如果是整机降频或网络整体变慢，所有连接一起变慢，这个前提不成立，一条都不会被淘汰，不会陷入「重连更慢、再淘汰」的循环；真正死掉的连接由 30 秒读超时兜底收尾。结论：不需要改，改了反而会放过真死的连接。

## 说明

- 升级方式不变：正式签名与之前一致，直接覆盖安装即可，不用卸载，任务记录都保留。
- 没有新增任何权限（磁贴用的是系统快捷设置的绑定机制）；没有新增任何第三方依赖。
- 安装包体积：以正式发布包实测为准（验收包约 1.3 MB 量级，仍在 1.5 MB 红线内）。
