# TuxunDown v7.4.0

这一版没有新功能，专做一件事：把每个任务的状态管严。下载器里每个任务都在排队、下载中、暂停、完成、失败这几种状态之间来回变，变错一次，轻则任务莫名其妙重新排队，重则下好的文件被当成没下完。这一版把全部状态变化过了一遍审计，又加了一道统一的守卫：不该变的状态，现在变不过去。

## 状态守卫与防误操作

- **状态变化有了统一守卫**：以前每个入口各自注意任务现在是什么状态、能不能变，难免有漏。现在所有关键的状态变化都先过同一张合法变化表：排队可以开始下载、下载中可以暂停，暂停可以继续，这些照常；正在下载的任务被重新排队、已经下完的任务被打回排队这类不合法的变化，会被直接拦下，不会真的发生。
- **拦下会被记下来**：每拦下一次，都会记下次数和最近一次的情况（哪个任务、从什么状态、想变成什么），不带任何链接信息。诊断页能看到这个计数，出了问题有据可查。
- **手动暂停的任务不会被抢跑**：你亲手暂停的任务，之后程序做恢复检查时不会再把它误当成「被打断的任务」自动排回队列。暂停就是暂停，只有你点继续它才会再动。
- **取消过的任务不会留下尾巴**：任务取消后，内部记着的取消标记现在会在更多出口被及时清掉，不会越积越多。

## 半成品补收尾

- **下完只差改名时被关掉，下次打开自动补完**：文件下载完之后还有一步收尾：把临时文件改成正式名字。以前如果恰好在这一步之前程序被关掉，记录里已经写着「完成」，文件却还留着半成品的名字，没有任何入口会再去补这一步。现在程序启动时会专门检查这类任务：记录是完成、正式文件还没落地、半成品文件确实还在的，会自动重新走一遍收尾，文件正常出现在下载目录里，不用重新下载。半成品文件不在的不会乱动，那种情况按原来的对账方式处理。

## 诊断页「任务状态分布」

- 诊断页在「存储健康」下面新增一栏「任务状态分布」，打开就能看到现在的任务全貌：排队、下载中、暂停、完成、失败各有多少个；有多少任务正在等网络恢复、等插上充电、等你完成公共 WiFi 登录；有多少任务正在被下载流程认领处理中。
- 本次运行里守卫拦下过多少次不合法的状态变化，也列在这一栏里，并写明这是本次打开程序以来的计数；拦下过的话，还会写清最近一次是哪个任务、想从什么状态变成什么状态、在哪一步被拦下，不带链接，放心复制报障。
- 这一栏只报个数，不显示链接等具体内容；某一项读不出来时，只少那一项，其他项照常显示，全部读不出来时整栏不显示。

## 一条已知限制

- 失败任务在自动重试的等待期间，如果程序被系统关掉或手机重启，这个任务会停在「失败」，剩下的自动重试不会再继续。手动点一次重试就能从断点接着下，之前下好的部分不会丢。原因和绕法已经写进仓库的「已知限制」页。

## 照例

- 升级方式不变：正式签名与之前一致，直接覆盖安装即可，不用卸载，任务记录都保留。
- 没有新增任何权限，权限仍是原来的 10 项；没有新增任何第三方依赖。
- 安装包体积以本页附带的正式包实测为准，并继续受 1.5 MB 体积守门约束（超过就发不出来）。
