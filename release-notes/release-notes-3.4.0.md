# TuxunDown v3.4.0

3.4.0 做两件新东西和一轮审计：设置里能清理旧任务记录了（只删记录不删文件，清理前自动备份）；统计页能把下载情况生成一段可复制、可分享的文字报告。第 20 轮审计查的是大数据量——任务记录攒到上千条时，列表、搜索、存盘、统计还顺不顺，修了导入备份的一处平方级慢点。

## 新功能

- **清理旧任务记录**（设置 → 引导与数据）：任务攒多了列表又长又乱，现在可以把 30 / 90 / 180 天前的已完成、已失败记录删掉（页面上会先告诉你当前符合条件的一共几条，点清理后还有一次确认，写明完成几条、失败几条）。规矩说死：
  - **只删记录**：已经下好的文件本体不动；没下完的 .part 也不动（它归同一组里的「清理孤儿 .part 文件」管）；
  - 正在排队、下载中、暂停中的记录永远不会被清——暂停的下载是下到一半的活，不是垃圾；
  - **清理前自动备份**：先把全部设置＋任务记录按标准备份格式存一个文件到下载目录（文件名带 before-cleanup），存成功了才开始删；存失败就一条都不删。这里选了「自动备份」而不是只弹一个确认框：确认框只能防点错的那一下，备份文件能让删完后悔也有退路——用「导入备份」选那个文件，记录就回来了（文件本来就没删，不需要恢复别的）。
- **下载报告**（统计页 → 下载报告）：把下载情况拼成一段纯文本，可复制、可分享。内容包括：本月完成几个文件、共多大、最大文件是哪个；全部记录的完成/失败数和成功率、单任务最快速度、最大文件；本机累计下载量、完成任务数、平均速度；下载最多的站点前五。数字全部现算现拼，没有数据的部分直接省略，不会拿 0 或猜测凑版面。报告末尾写明每个数字的来源：累计统计是 App 在本机的总账（删记录不影响它），成功率、最快速度、最大文件按现在还留着的任务记录算（删掉的记录不算在内），本月按完成时间算。报告只在本机生成，不上传。
- **失败任务现在记失败时间**：以前只有下载成功才记完成时间，失败任务没有时间戳。这一版起，下载失败的那一刻会记下来（每次开跑先清掉上一次的旧戳，不会张冠李戴）。清理旧记录和下载报告对失败的计时从此是准的；老版本留下的失败记录没有这个戳，按创建时间兜底——只会比真实失败时间删得晚，不会误删。

## 审计（第 20 轮：大数据量）

用 1,500 条「肥」记录（带分片位图、90 点速度历史、请求头）当合成数据，把主要数据路径逐条核了一遍：

- **修：导入备份是平方级的**。导入时，每条待导入记录都要拿 id 和链接对整个现有列表各扫一遍查重——1,000 条的备份导进已有 1,000 条的列表，就是约 200 万次字符串比较；而且每收下记录还要把整张表复制一遍（列表是写时复制结构）。现在改成：先用集合把「哪些收、哪些跳过」一次性算完（纯逻辑，带单测），再一次性并入。查重规则一条没变——包括备份文件自己内部有重复时，后面的照样会被先收下的挡住。
- **同类问题在新功能里当场避开**：批量删记录新加了一次性删除＋一次落盘（removeAll），清理几百条旧记录不会变成几百次全量写盘。
- **核过成立（量级结论）**：
  - 列表筛选、搜索筛选是线性扫描，排序 O(n log n)；全局搜索对任务表走两遍线性扫描（每条最多几次子串匹配，站点解析放在最后、前面命中就短路）；按站点分组单遍成组；队列每次取下一个任务 O(n)，而同时下载数有上限，不会放大。
  - 任务存盘是全量序列化，成本随记录数线性：单条记录约 1–2 KB（90 点速度历史是大头），1,500 条时文件约 2–3 MB；每次落盘要写临时文件、备份旧文件、改名，约 3 倍文件大小的写入量，但有 1.5 秒合并写节流封顶（下载中最多 1.5 秒写一次），结构性的增删则立即落盘。已加 1,500 条规模的常驻单测，钉住序列化往返不丢条、体积不失控。
  - 统计聚合与任务数无关：站点统计最多留 50 条、按天序列最多 31 天，读写都是定长小数据；每次下载完成时的统计记账也是常数级。
  - 自动归档清扫每次启动只在后台线程扫一遍 O(n)，改设置时再扫一遍；不是每帧、每秒跑的东西。下载服务每秒一次的通知汇总同样是线性一遍。
- **如实标注**：列表在真机上的滚动流畅度（尤其是大字体下）没法在本地核，只能真机看；1,500 条时主页每次刷新有几遍线性扫描，量级上没问题，实际帧率以真机为准。

## 说明

- 升级方式不变：正式签名与之前一致，直接覆盖安装即可，不用卸载，任务记录都保留。
- 没有新增任何权限；没有新增任何第三方依赖（清理、报告、审计修复都是本地纯逻辑与既有组件的重新接线）。
- 安装包体积：以正式发布包实测为准（验收包约 1.3 MB 量级，仍在 1.5 MB 红线内）。
