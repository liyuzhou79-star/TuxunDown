# TuxunDown v6.1.0

这一版的主题是发热与温控。长时间下载大文件时，手机发热、系统降速是常见情况，以前 App 对此毫无感知：既不显示，也不会提醒，速度变慢时很容易误以为是网络出了问题。这一版先把温控状态做成看得见的信息，同时对保持运行的唤醒锁做了一轮完整审计和一处实际修复。发热时只提示、不干预，是这一版明确的取舍。

## 新功能

- **一键体检新增「设备温控」**：诊断页的一键体检多了一项「设备温控」，把手机当前的温控状态分成三档显示——正常、偏热、发热降速中。「偏热」表示系统已经开始小幅压低性能、设备还能应付；到了「发热降速中」，说明设备正在主动压低性能散热，这时下载变慢可能不是网络的问题，体检结果里会把这句话写明。体检仍然是点了才读一次当前状态，不在后台持续监测。如果这台手机读不到温控状态（比如厂商接口不提供），这一项就直接不显示，不会编一个假状态出来。
- **下载中发热提示**：正在下载时，如果手机进入发热降速状态，下载通知里会多写一句提醒：手机发热降速中，速度变慢可能不是网络的问题。这条提示只负责提醒，不会自动暂停下载、不会自动降低速度，下载照常进行——要不要停下来让手机凉一会儿，由你自己决定。

## 优化

- **「下载中保持运行」开关即时生效**：以前这个开关是在一次下载开始时读一次的，下载途中把它关掉，要等当前任务下完才真正放开。现在下载途中改开关，约一秒内就按新设置走：关掉就及时放开，不再白白保持运行；打开也会及时生效。

## 修复

- **保持运行状态与开关不一致的问题**：上面这条优化修的正是一个实际问题——长任务下载途中关掉「下载中保持运行」后，处理器仍会一直保持运行到任务结束，与刚刚改过的设置不符。现在开关、实际保持状态和设置界面三者一致，且一个任务的改动不会影响其他正在下载的任务。

## 说明

- **唤醒锁审计结论**：这一版对下载期间保持处理器运行的唤醒锁做了完整审计，逐条核对了分片、流媒体、FTP、单连接、排队等待、失败重试等待和收尾处理等所有路径，结论是没有发现该放没放的漏放：真正传输时才持有，等待和收尾阶段不占用，所有路径结束时都会释放。审计中另有两处经评估后维持现状：一是唤醒锁的无超时获取方式——改成定时获取反而可能在超长下载中途悄悄失效，现有的成对获取与释放已经核实可靠；二是获取时机保持在下载开始处——挪到更靠后的位置需要把现在单一的获取与释放拆散到各条下载路径里，收益有限、风险更大。这两处都把理由记在了代码和审计记录里，不是漏改。
- **启动器图标字形略缩小**：桌面启动器图标里的 T 字箭头字形略微缩小了一圈（约九成），在桌面上看着不再偏大；App 内的图标不变。
- 升级方式不变：正式签名与之前一致，直接覆盖安装即可，不用卸载，任务记录都保留。
- 没有新增任何权限，温控状态读取不需要额外权限；没有新增任何第三方依赖。
- 安装包体积以本页附带的正式包实测为准，并继续受 1.5 MB 体积守门约束（超过就发不出来）。
