# TuxunDown v8.0.0

这一版是整合版：没有新功能。做的事情是把 7.1 到 7.9 一整轮加过的功能重新逐项复核了一遍，再把发布前的总审和说明文档全部对齐到现在的实际行为。图的是踏实——功能加得快，更要确认每一项到今天仍然真的接通、真的生效。

## 全量回归自检

- **17 组功能逐项复核，全部接通**：排队公平与防饥饿老化、安全脱敏、存储自愈、任务状态守卫、收尾中显示、功耗分级、资源诊断、单任务最多 128 条连接、极速开局、极速收尾、删除文件、详情按钮收紧、尾巴双下、渐进放行、多任务预算按实时目标分摊、流媒体（HLS）起步形态对齐、诊断页的放行形态行——每一组都找到了程序里实际生效的接线点，逐项确认，没有发现断线，也没有发现回退。
- **复核只认实际接线，不认「写过」**：每一项都落到具体的代码位置核对，而不是翻更新日志就算数；结论是这一轮的功能到今天都还在正常工作。

## 发布总审

- **版本号链逐版核对**：从已发布安装包里逐版读回版本号确认连续递进，这一版是 8.0.0、内部版本号 71，承接上一版的 70，只进一位，没有跳号也没有重号。
- **检查更新的跨版本比较补了专门测试**：7.9.0 会正常提示升级到 8.0.0；反过来，8.0.0 不会被任何旧版本反向提示更新，这条边界已经用自动测试钉死。
- **版本与签名指纹各处同源**：程序里显示的版本号和签名指纹都取自手机上实际安装的安装包本身，各处显示一致，不会出现一处新、一处旧。
- **备份往返一致**：设置和任务记录导出成迁移包、再导入、再导出，结果一致；本机专属的目标位置照旧不进备份，带凭据的内容照旧剔除，不会因为备份把敏感信息带出去。
- **「瞬间满开」默认关闭在正式构建里确认生效**：不只看源代码里的默认值，还确认了正式发布流程里没有任何地方能把它悄悄打开——发布构建在打包前会先跑一遍自动检查，默认值被改动就过不了关。

## 文档同步

- **帮助中心补齐到 38 个话题**：补上了删除文件、尾巴双下（实验）、连接放行形态 3 个此前缺失的话题；另有 5 处旧说法按现在的实际行为修订，包括新任务起步条数、连接数对比结果的应用方式、连接预算的归因口径。
- **「已知限制」补齐到 23 条**：新增两条——「瞬间满开」默认关闭（背景仍只能写疑似：个别服务器对瞬间并发的限速从外面看不透，没法实锤，只能把开局放稳，避开嫌疑最大的动作）、「尾巴双下」默认关闭的实验性质（重复流量有硬上限：不超过文件 1%、最多 4 MB）；其余条目逐条复核，仍然成立。
- **仓库首页口径改准一处**：首页里「新任务 32 条爆发开局」的旧说法已经不成立——在出厂的渐进放行形态下，新站点先开一批起步，32 只是后续加宽的上限，首页文案已按现在的实际行为改准；连接预算的说明也同步到按实时目标分摊的新口径。

## 照例

- 升级方式不变：正式签名与之前一致，直接覆盖安装即可，不用卸载，任务记录都保留。
- 没有新增任何权限，权限仍是原来的 10 项；没有新增任何第三方依赖。
- 安装包体积以本页附带的正式包实测为准，并继续受 1.5 MB 体积守门约束（超过就发不出来）。
