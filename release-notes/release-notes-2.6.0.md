# TuxunDown v2.6.0

2.6.0 做了三件事：重启/被杀恢复——手机重启或下载进程被系统杀掉之后，未完成的任务有了明确、可靠的恢复路径（带一个默认关的「开机自动恢复」开关）；按类型分文件夹（默认关）——新下完的文件可以按类型进「下载」里的分类子文件夹；第 12 轮审计——通知、桌面小部件、主页三处状态数字改成同一套算法，并顺带给 https 连接加了 IPv6/IPv4 双栈竞速。

## 新功能

- **开机后自动恢复未完成任务**（设置 → 下载，默认关）：开启后，手机重启完成，没下完的任务会按队列自动接着下。恢复不是无条件蛮干：「仅 WiFi 下载」开着时仍然等 WiFi，流量保护仍然拦未确认的大文件，预约时间没到的任务仍然等时间。**你亲手暂停的任务永远不会被自动恢复**——暂停是你的决定，不是事故。
- **进程被杀后的恢复补上了洞**：以前下载中进程被系统杀掉、服务被系统重新拉起时，排队中的任务会自己续上，但**正在下的那个任务会停在「暂停」状态等人手动点继续**（文件字节和断点都完好，就是没人推它一把）。这一版把这条路径修通了：被系统中断的任务在服务重启时自动重新排队。反复崩溃触发安全模式时例外——那种情况下由你决定接下来跑什么，不自动恢复。
- **按类型分文件夹**（设置 → 下载，默认关）：开启后，新下载完成的文件按类型落进公共「下载」目录的子文件夹：视频 / 音频 / 图片 / 文档 / 压缩包 / APK；认不出类型的文件仍留在「下载」第一层。规矩说清楚：默认关时行为和以前完全一样（文件就在「下载」第一层）；已经下好的文件不搬家；下载中途改开关不会把一个文件劈到两个文件夹；使用自定义下载文件夹时此项不生效（那个文件夹是你自己选的，按原样用）。

## 优化

- **连接竞速（Happy Eyeballs）**：服务器域名同时有 IPv6 和 IPv4 地址时，两条路错开 250 毫秒同时发起连接，谁先连通就用谁下，不再在一条不通的路上等到超时才换。范围如实说明：只对 https 直连生效——普通 http 的连接方式系统没有开放替换的口子，维持原样；走代理时由代理解析连接，也不参与竞速；只有一个地址族的服务器不会触发竞速。竞速任何一步失败都会退回系统原来的连法，最坏情况和以前一样。
- **第 12 轮审计：三处状态数字归一**。主页顶部汇总卡、下载进度通知、桌面小部件以前各自算一遍总进度：总数口径本来就一致（都是「下载中＋排队中」），但百分比的算法有细微差别——主页卡片用浮点数算，大文件时可能比通知和部件少 1%。这一版三处共用同一份聚合计算（同一套整数算法、同一个任务口径），数字在任何稳定时刻都完全一致；刷新节拍（约 1 秒）带来的先后差别仍在，那是节拍不是算错。另外复核了通知编号：进度通知与完成通知各用各的编号、互不覆盖，完成通知的「单条」与「合并汇总」共用一个编号是有意为之（后到的汇总会替换先前的单条，不堆叠）。

## 说明

- 升级方式不变：正式签名与之前一致，直接覆盖安装即可，不用卸载，任务记录都保留。
- 新增权限一个：RECEIVE_BOOT_COMPLETED（接收开机广播），只服务于默认关的「开机自动恢复」开关；开关关着时，开机时 App 只读一下这个开关就退出，不做任何下载动作。
- 安装包体积：以正式发布包实测为准（验收包约 1.27 MB 量级，没有变臃肿）；没有新增任何第三方依赖。
