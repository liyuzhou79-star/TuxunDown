# TuxunDown v4.2.0

4.2.0 是一版速度专项：单个任务能开的连接更多、开局起步更快、大文件的分片切法更聪明、正式开下前先把连接热好，另外给诊断页加了一个「连接数对比实测」，让你能亲手量一量自己的链接到底吃多少连接最快。这一版没有承诺任何倍数——快不快取决于你的网络和对方服务器的做法，下面只讲具体改了什么。

## 新功能

- **诊断页新增「连接数对比实测」**：设置里的一键诊断页多了一个小节。填入你自己的下载链接（会自动带上最近一个任务的链接，也可以粘贴），分别用 4 / 16 / 32 / 64 条连接各测一段稳态速度，最后标出哪个连接数最快。开始前会先弹出说明：四档一共最多用多少流量，你确认了才开始；测到一半可以取消，已经测完的档位会保留。要注意，这测的是「这个链接在你当前网络下吃多少连接」，和测速页的服务器测速不是一回事；如果实测时有别的任务正在下载，它们会抢带宽、结果会偏低，页面上会写明开始时有几个任务在跑。

## 优化

- **单个任务最多 64 条连接**：以前单个任务最多开 32 条连接，现在上限翻倍到 64 条；全局连接上限（所有任务合计）的可调范围也从最高 64 条放宽到 128 条，设置里多了两档可选，默认值仍然是 32 条，没有动。对按单条连接限速的服务器，连接多开一些，速度就能多抢回来一些；如果某台服务器扛不住、被限流过，App 记住的上限照样管着每一次起步，不会硬冲。连接变多带来的内存开销也算过账：每个任务的接收缓冲总量封顶不变，连接再多也不会成倍吃内存。
- **新任务 16 条连接爆发开局**：以前新任务从 4 条连接起步、一档档往上试探，爬到合适的连接数要等好几轮。这一版改成：服务器没下过的新链接，直接 16 条连接开局，再根据实测速度往上加或往回收；在这台服务器下过、记得最佳连接数的，照旧按记住的数起步；暂停后继续的任务，按上次实际用的连接数接着开，不再从头试探。
- **大文件分片前细后粗**：256 MB 以上的大文件，分片不再从头到尾一个大小：前面一段切成更小的块，后面保持大块。前段切得细，暂停、断网恢复、续传时进度更跟手，慢块也更容易被下完的连接接手帮忙；后段的大块保证整体效率。已经下了一半的任务不受影响——分片的切法在任务创建时就定死并存好，续传时原样沿用，不会错位。
- **开下前先热身连接**：任务一开始，后台先把服务器域名解析好、把第一条连接预先建好放进连接池，正式探测和第一批分片直接就能用，少等一轮建连和加密握手。热身失败不报错、不挡下载，照常走原来的流程。用了代理时不做直连热身（那会绕开代理），FTP 链接也不走这条路。

## 修复

- **审计第 27 轮（速度改动的连带检查）**：这一轮专查上面这些改动会不会互相打架。查实并修了两处：一是连接数实测和正在下载的任务会互相抢带宽——实测开始时会数一下有几个任务在跑，结果旁会写明，避免你拿偏低的数字当结论；二是连接数被调低后，正在收尾的旧连接新分配的缓冲可能超出预算——改成按「目标连接数和实际在跑连接数里更大的那个」算缓冲，任何时刻单个任务的缓冲总量都封顶在预算内。其余几处（自动调连接数和全局上限、和服务器限流记忆之间的配合，64 条连接时每秒的状态统计开销，热身和双通道 / 代理 / 流媒体的交叉，分片新切法和断点续传的对账）逐项查过，结论是不会互相干扰，依据都记在项目的检查点文档里。

## 说明

- 升级方式不变：正式签名与之前一致，直接覆盖安装即可，不用卸载，任务记录都保留。
- 没有新增任何权限；没有新增任何第三方依赖。本版的起步策略、分片切法、热身判断、实测结论都是纯逻辑，带单元测试。
- 安装包体积：以正式发布包实测为准（仍在 1.5 MB 红线内）。
