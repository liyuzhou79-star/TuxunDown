# TuxunDown v4.5.0

4.5.0 主要做四件事：把「下载失败后怎么办」的判断方式换了个更可靠的底子；让排队的任务提前热身、轮到时开局更快；文件校验提速并且能看到进度；下完的速度曲线可以导出成表格慢慢看。没有承诺任何速度倍数，下面只讲具体改了什么。

## 新功能

- **速度曲线可导出 CSV**：下载完成的任务，展开卡片就能把这次下载的速度曲线导出成一个 CSV 表格，存到公共「下载」目录（或你自选的下载文件夹），用任意表格软件打开就能看、能画图。表格三列：经过的秒数、累计字节、那一秒的速度。需要说明的是，累计字节是按每秒的速度记录推算出来的，表格开头的注释会把这件事写清楚，不冒充精确测量；曲线最多保留最近 90 秒。任务没有留下曲线时，会直接提示导不了，不会生成一个空文件糊弄你。

## 优化

- **排队预热，轮到时开局更快**：以前一个任务要等排在前面的下完、轮到自己时，才开始解析服务器地址、建立连接。现在只要有任务正在下载，排在第一位的下一个任务就会提前把地址解析好、把连接热上，轮到它时少等这一步。护栏是齐的：只在 WiFi 或 WiFi＋流量双通道时做，纯流量不做；流量保护开着直接不做；用了下载代理也不做（代理下地址由代理解析）；同一时间只热一个任务。热身失败不影响任何事——正式开始时，解析、连接、探测都会照常完整重来一遍，它只是一个连接层的提前量，不是正确性的一部分。
- **校验提速，进度看得见**：下完文件做完整性校验（对 SHA-256 / MD5）时，读取缓冲从 256 KB 加大到 1 MB，来回读取的次数降到四分之一，校验更快。校验过程中，卡片上会实时显示「正在校验…N%」，大文件不用再对着一个不知道走到哪的状态干等；文件大小实在取不到时就只显示「校验中…」，不编百分比。取消校验的方式和以前一样。另外补了一个护栏：同一个任务同时只会跑一份校验，从卡片手动校验和下完自动校验撞上时，后来的会自动让开，不会互相覆盖结果。

## 修复

- **失败原因的判断换了底子，建议和自动重试不再靠猜字眼**：以前失败卡片上的处理建议、以及「这种失败还要不要自动重试」的判断，是靠在失败说明文字里找关键词做的。这有个隐患：说明文字是为了让人看懂写的，措辞一调整，判断就可能悄悄失效或者误判——上一版修好的「断网停泊」就曾经因为同样的原因失效过（判断看的是翻译后的文字，关键词根本不存在）。这一版把整条链路排查了一遍：失败原因改在出错的那一刻、原始信息还在的地方按类型记下来（服务器返回的状态码、存储空间不足、存储设备没了、目录授权失效、文件已被删、网络问题等），并且写进任务记录，App 重启之后还在。卡片建议和自动重试的开关都改为按这个类型判断，说明文字以后怎么改都不会再影响判断。顺带补上了一个以前完全没建议的情况：文件在下载途中被删掉导致失败时，现在会明确告诉你发生了什么、建议重新下载。老版本留下的、没有类型记录的失败任务，仍按原来的文字方式给建议，不会没人管。

## 说明

- 本轮还逐项核查了其他几处「按文字做决定」的地方：嗅探的路线判断看的是服务器返回的内容类型（协议数据，不是错误文字）、断网判断看的是原始异常，结论是行为正确，没有改动，这里就不包装成新功能了。
- 升级方式不变：正式签名与之前一致，直接覆盖安装即可，不用卸载，任务记录都保留。
- 没有新增任何权限；没有新增任何第三方依赖。本版的失败分类、排队预热判断、校验进度计算和曲线导出格式都是纯逻辑，带单元测试。
- 安装包体积：以正式发布包实测为准（仍在 1.5 MB 红线内）。
