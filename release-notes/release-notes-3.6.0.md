# TuxunDown v3.6.0

3.6.0 做两件看得见的新东西和一轮总审：完整迁移包——换手机时把设置、任务、嗅探历史、下载统计和按主机学习数据一个文件全带走；关于页新增更新日志——从 1.2 到这一版每个版本变了什么，在 App 里一页看完。第 22 轮审计是发布就绪总审：站在「明天就正式发布」的角度，把版本号链、检查更新、关于页显示、新手引导、混淆后的反射面、发布说明与功能对账、README 与仓库现状逐项核过。

## 新功能

- **完整迁移包**（设置 → 引导与数据 →「导出完整迁移包」）：一个 JSON 文件装下全部设置＋任务记录＋嗅探历史＋下载统计＋按主机学习数据（每个站记住的最佳线程数和限流上限）。换手机或重装后，在新设备上用「导入备份」选这个文件，一次全恢复——统计页攒下的累计数字、和「这个站下过、直接满速起步」的学习成果都不用从零再攒。敏感信息沿用一贯的剔除规则：每个任务的 Cookie、Authorization、Proxy-Authorization 都不进迁移包，代理密码也不进（导入后重填一次）；下载目录不在包里（文件夹授权没法跨设备，导入后在设置里重选一次）。
- **更新日志**（设置 → 关于 →「更新日志」）：1.2 到 3.6 每个版本一句话要点，离线内置在 App 里，不用联网、不用去 GitHub 翻发布页。

## 兼容性

- 导入端向下兼容：以前导出的普通备份（只有设置＋任务，格式版本 1）和最早的任务列表文件（纯任务数组）照常能导入，只是没有统计和学习数据部分——导入时这两部分保持新设备上的现状不动，不会清零。
- 迁移包格式带版本号（格式版本 2），以后的版本会继续认它。

## 审计（第 22 轮：发布就绪总审）

- **版本号链**：从 1.1（versionCode 2）到 3.6（versionCode 27）逐个列出核对，单调递增、无跳号无重号，覆盖安装不会被系统拒绝。
- **检查更新**：版本比较是纯数字逐段比较，1.2 → 3.6 整条链的顺序、以及 3.10 > 3.9 这类两位数段都钉了单元测试；装得比发布页新时不会反过来提示「有更新」。
- **关于页与引导**：版本号取自系统实际安装信息（不是写死的字符串），关于页、诊断页和新手引导共用这一个值；诊断页的签名指纹是运行时从安装包证书现算的——两处显示与安装包天然一致。新手引导按版本号变化触发，3.6 首次打开会照常弹。
- **混淆与反射面**：全仓没有 Class.forName、Gson、Moshi、kotlinx.serialization 这类靠反射的序列化——任务与备份的存取全是手写 org.json、键名是字符串字面量，R8 改名不影响旧存档可读性；内置浏览器没有注册任何 Javascript 桥（页面里的 JS 调不进 App），WebView 回调类已有 keep 规则兜底。
- **文档对账**：本说明每条都能在代码里找到对应实现；README 的功能列表同步补了完整迁移包、找重复文件和分片进度图。README 里没有写死版本号的下载区，不存在过期链接。

## 说明

- 升级方式不变：正式签名与之前一致，直接覆盖安装即可，不用卸载，任务记录都保留。
- 没有新增任何权限；没有新增任何第三方依赖。
- 安装包体积：以正式发布包实测为准（验收包约 1.3 MB 量级，仍在 1.5 MB 红线内）。
