# TuxunDown v3.3.0

3.3.0 做两件新东西和一轮审计：主页搜索升级为全局搜索（任务、已下载文件、嗅探历史一次搜完）；任务列表新增「按站点」分组视图。第 19 轮审计是组合并发——单项都验过的几个提速机制（动态加减连接、收尾劈片、优先级带宽分配、限速计划切换、限流上限学习）专核它们在同一时刻相遇时会不会互相拆台，修了两个真问题。

## 新功能

- **全局搜索**（主页搜索框）：以前搜索只是在当前标签页里筛任务。现在输入关键词，会同时搜三样并分三组列出：
  - **任务**：文件名、链接、你写的备注、下载站点都算匹配，而且跨全部标签、连已经自动归档的记录也能搜到——命中直接就是完整的任务卡片，暂停、继续、打开等所有操作当场能用。任务组沿用列表的排序方式（默认 / 大小 / 时间）。
  - **已下载文件**：按文件名搜下好的文件，点一下跳到「已下载文件」页。如实说明：这里搜的是有任务记录的文件；下载目录里没有任务记录的文件（比如手动放进去的）请在文件页里找，搜索不会为了每个按键去重扫整个文件夹。
  - **嗅探历史**：嗅探过的网页按链接（历史只存了链接、没存网页标题）搜，点一下把那个网页填进新建下载框重新嗅探。
  - 清空搜索就回到原来的任务列表；搜索时多选栏的「全选」选的是搜索结果，这点也对齐了。
- **按站点分组**（主页「视图：平铺 / 按站点」）：任务多了可以按下载站点归类。每个站点一个组头：站点名、这组有几个任务、这组总共下了百分之多少（大小还不知道的任务不参与这个比例，不猜）。点组头折叠 / 展开，折叠状态会记住（关掉 App 再开还在，也跟着备份走）。和现有功能的关系写死在规矩里：标签（全部 / 下载中 / 已完成 / 失败 / 已归档）先筛，分组只收标签筛剩的；排序只在每个分组内部生效，不会把组打散；全局搜索时不用分组（搜索有自己的三组）；宽屏双列只在平铺视图下有，分组视图单列，组头占满整行。

## 审计（第 19 轮：组合并发互作用）

这一轮不看单个机制，只看组合：五个机制在同一任务、同一时刻相遇时的判定顺序和互相覆盖。逐组核完，修了两个真问题，其余组合结论成立：

- **修：收尾劈片 × 自动减连接——切好的尾巴可能没人接**。下载收尾时，最慢的那块会被切成几片分给空闲连接（劈片），切好的片先排队、等连接来领。负责执行的连接在「回头拿下一块」时先过一道检查：如果动态伸缩刚把目标连接数调低，多出来的连接在这里直接退出——这道检查排在「去领排队的尾巴」之前。正常情况下没事：留下的连接会把尾巴领完。但这道检查和连接计数不是原子的：几个连接同时下完手里的活、同时来过这道检查时，可能个个都以为自己是「多出来的」，一起退出，在岗数直接跌到零；而采样器的「缺人补位」只在还有全新分片时才补人，收尾阶段没有全新分片，永远补不回来——任务会在只剩尾巴没下完时以「部分分片下载失败」收场，字节明明都还能下。现在规矩改成：只要还有切好的尾巴在排队，连接就不算「多余」，先领一片再说；排队为空才准退出。这条规则是纯逻辑，带单测钉死。
- **修：普通失败的「忘记」会连限流上限一起忘掉**。同一台服务器在 App 里记着两件事：「最佳连接数」和「限流上限」（之前多连接被它拒绝过学来的）。这两件记在同一条记录里，而「连续失败两次就忘掉这家」的老规矩（v1.5）删的是整条记录：因为断网、文件被删这类普通原因失败两次，限流上限会跟着被忘掉，下次又从满连接数冲上去，把同一次限流原样再挨一遍才重新学会。现在忘记只忘连接数：上限保留为一条「只有上限」的记录，重新试探时照样受它约束；上限本身仍按原规矩随成功逐步放宽、按 30 天过期。组合链（限流证据 → 学上限 → 两次失败 → 上限还在 → 在上限处完成又能放宽）已补成常驻单测。
- **核过成立的组合（摘录）**：
  - 限流上限 × 动态伸缩：上限在下载开始时就写进伸缩器的最大值，试探阶梯和稳态加连接都越不过它，不是「先冲上去再被拦」；本次下载中新出现的限流证据只在整场失败后才结算、下一场生效——本场靠自动减连接和重试自愈，不会中途改判。
  - 限流证据的连接数口径：记录的是当时的目标连接数；减连接的过渡期里实际连接可能短暂多于目标，结算出的上限只会偏保守（更低），不会学出一个过高的上限。
  - 限速计划过点 × 令牌桶：限速值每次限速时现读，过点（比如 23:00 进入夜间档）立刻生效，不用重启任务；切到「不限」时之前攒的限速欠账直接作废、立刻全速；切到更低档时最多有约 1 秒的突发余量，不会出现长时间超速或长时间卡住。
  - 限速计划过点 × 动态伸缩：限速造成的速度变化会被伸缩器当成「服务器变快 / 变慢」的信号——在限速档内减连接不掉速，伸缩器会收敛到更少的连接（省电、少挨拒绝，是好事）；时段结束恢复全速后，加连接信号会把连接数再涨回来。不会来回震荡：伸缩器本来就有「改完要观察两轮才准再改」的防抖。
  - 三档优先级 × 其余：优先级只管两件事——排队顺序和全局限速的带宽分配比例（高 : 中 : 低 = 2 : 1 : 0.5），都是每次现读现算，改完立刻生效；它不管连接数，低优先级任务照样可以开满连接，只是字节份额小。两者各管一维，不互相覆盖。

## 说明

- 升级方式不变：正式签名与之前一致，直接覆盖安装即可，不用卸载，任务记录都保留。
- 新增的两个界面偏好（是否按站点分组、哪些组折叠着）都进了备份的设置快照，恢复备份后原样回来。
- 没有新增任何权限；没有新增任何第三方依赖（全局搜索、分组、审计修复都是本地纯逻辑与既有组件的重新接线）。
- 安装包体积：以正式发布包实测为准（验收包约 1.3 MB 量级，仍在 1.5 MB 红线内）。
