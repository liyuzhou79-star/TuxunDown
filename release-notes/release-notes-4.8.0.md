# TuxunDown v4.8.0

4.8.0 主要做三件事：FTP 下载支持多连接分片；排队改为按站点轮转，异站任务不再被同站长队饿着；把最近几版新增的任务字段逐项核对了一遍存取与备份导入，顺带修掉几个坏数据的小毛病。没有承诺任何速度倍数，下面只讲具体改了什么。

## 新功能

- **FTP 多连接分片下载**：以前 FTP 链接只有一条连接从头下到尾。现在开始下载前会先探测服务器：能报出文件大小、且支持断点续传（REST）时，文件会像普通链接一样切成分片，最多 8 条连接同时下载（实际条数还会受任务自身的连接数设置和全局连接上限约束），卡片上会写明「FTP 多连接下载：N 条连接一起下」。分片进度和普通任务一样保存，暂停、重启后照样接着下。
- **以前 FTP 下到一半的任务能接上**：升级前用单连接下了一部分的 FTP 任务，升级后第一次继续下载时，已经下好的整段会直接认账，剩下的部分再用多连接接着下，卡片上会写明接上了多少；如果文件其实已经下完了，会直接收尾，不会重下。

## 优化

- **排队按站点轮转**：同时下载个数有限时，以前严格按排队顺序取任务——前面排了一长串同一个网站的任务，后面的其它网站任务就一直轮不上。现在同优先级里改成按站点轮转：刚开始过任务的站点先让一让，优先取一个其它站点的任务，轮完一圈再回来。优先级规则不变（高优先级仍先于低优先级），你手动「插队」的任务仍然最优先、下一个就开始。轮转记忆只在本次运行内有效，重启 App 后从排队顺序重新开始，不写进任务记录和备份。

## 修复

- **FTP 不支持分片时如实回退单连接**：服务器不报文件大小、或不支持断点续传时，照旧用单连接下载，卡片上会写清是哪种原因（比如「不报文件大小（SIZE），没法分片，已用单连接下载」）；文件太小、分片没有意义时也一样单连接并写明。有些服务器限制同一账号只能登录一次：多余的连接会安静退出，剩下的连接继续下，不会因为开不了更多连接就整个失败。
- **任务记录与备份一致性核对（稳定性）**：这一项不是新功能，是把最近几版陆续新增的字段——分片细分区参数、失败类型与状态码、峰值连接数、各下载源各下了多少、校验状态、速度记录、重试计数、请求头等——逐项核对了保存、读取和备份导入（包括很老的备份格式），并用专门的测试把每一代的记录形状和往返结果钉住。核对中修掉的坏数据毛病举几个例子：某个请求头的值写坏时，以前会连累整条任务记录被丢弃，现在只跳过坏的那一项、记录保住；重试计数被写成负数时会让任务多重试，现在读取时归零修正；峰值连接数被写成离谱的大数时，服务器画像会显示乱码数字，现在读取时按实际上限收住；校验状态、速度记录的异常值也做了同样的归一处理。正常使用的任务记录不受影响，这些修正只在数据本身已经损坏时才触发。

## 说明

- FTP 多连接的适用条件再说清一次：服务器要能报文件大小并且支持断点续传，两个条件缺一就单连接；连接数上限 8 是按公共 FTP 服务器常见的同时连接限制定的，服务器只允许一条连接时就退化为单连接下载，不会反复硬闯。
- 升级方式不变：正式签名与之前一致，直接覆盖安装即可，不用卸载，任务记录都保留。
- 没有新增任何权限；没有新增任何第三方依赖。本版的 FTP 分片判定、排队轮转规则和字段核对都有单元测试。
- 安装包体积：以正式发布包实测为准（仍在 1.5 MB 红线内）。
