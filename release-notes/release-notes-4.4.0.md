# TuxunDown v4.4.0

4.4.0 主要收拾「网络环境变了，下载怎么办」这一类问题，再加三处体验优化：公共 WiFi 要登录时任务会停下来等你；中途断网改成停泊等恢复，不再直接失败；下完后的收尾不再占着下载位置；汇总卡能估算全部下完还要多久；新任务点下就开下，不再被队列的等待拖住。没有承诺任何速度倍数，下面只讲具体改了什么。

## 新功能

- **汇总卡显示「全部下完大约 X」**：主页汇总卡在总速度旁边多了一句估计，按当前所有正在下载任务的总速度、和还没下完的总量（包括排队任务的剩余量）算出来，让你一眼知道这一批还要多久。速度为零、或者有正在排队/下载的任务大小未知时，这句就不显示——算不准就不编数字。

## 优化

- **下完收尾不再占着下载位置**：以前一个文件下完之后，改名、按校验值核对整个文件、自动解压这些收尾工作都还在下载位置上做，文件越大、排在后面的任务等得越久。现在收尾改走一条专门的流程，下载位置立刻让出来，后面的任务马上开下。完成通知的时机没变：仍然是全部收尾做完之后才发；在收尾途中删掉任务卡片，也仍然按原来的规则处理（记录删掉、下好的文件保留，不会半路发完成通知）。
- **新任务点下就开下**：以前队列正在等预约时间、等插电、等网络恢复这类等待时段时，新加的任务会被一起拖住，最长可能等上约 30 秒才开始。现在等待会被新任务立刻唤醒，符合条件的任务马上开下。另外，新任务入队时会顺手预先解析一次服务器地址，真正开下时少等一步；开了下载代理时不做这一步（代理下地址由代理解析）。

## 修复

- **公共 WiFi 要登录时，任务停下来等你登录**：商场、车站、校园网这类 WiFi，连上后要先打开浏览器登录才能上网。以前下载任务撞上登录页会直接失败，你登录完还得手动点继续；更糟的一种情况是，登录页本身可能被当成文件存下来、还报「下载完成」。现在探测、续传、分片、单线程和流媒体下载都会统一识别「这是一个网页，不是文件」：任务会先停泊下来，卡片上写明请先完成 WiFi 登录，你登录完之后任务自动接着下，不用手动操作。已经能正常上网的网络上收到网页回复时，仍然按网页链接如实提示，不会乱停泊。
- **中途断网不再直接失败**：下载到一半切换网络（比如 WiFi 和流量之间切换）、开关飞行模式、切换 VPN，都会造成短暂断网。以前这种断网会让任务一路重试到失败、已经下的进度白白浪费，还得你手动重来。现在任务会先停泊下来等网络恢复，网络一回来就自动从断点继续。
- **双通道下载中流量网络消失，新任务不再拿到失效网络**：开着 WiFi＋流量双通道下载时，如果流量网络中途没了（比如关了流量开关），以前在同一次运行里新开始的任务还可能被分到那条已经失效的网络上。现在流量网络一消失就会被清掉，新任务只用还活着的网络；已经在下的任务遇到某条通道断了，也会自动改走另一条。

## 说明

- 本轮还逐项核查了连接超时、IPv6 网络下的建连、开 VPN 时的「仅 WiFi」判断，结论是现有行为正确，没有改动，这里就不包装成新功能了。
- 升级方式不变：正式签名与之前一致，直接覆盖安装即可，不用卸载，任务记录都保留。
- 没有新增任何权限；没有新增任何第三方依赖。本版的网页识别、断网判断、收尾流程、时间估计和唤醒逻辑都是纯逻辑，带单元测试。
- 安装包体积：以正式发布包实测为准（仍在 1.5 MB 红线内）。
